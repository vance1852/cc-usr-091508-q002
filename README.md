# 发射场勤务区撤离放行

本项目面向发射场地面保障和指挥团队，用于核对倒计时管制前各危险区的人员、车辆与设备撤离情况。

系统需要保留区域版本、班组确认和门禁回执，使冻结、复核与最终放行都有清晰的安全依据。

## 功能概览

勤务区撤离放行服务（Go + Fiber + SQLite）把以下对象关联成一致的清场结论：

- **危险区版本**：区域边界每次变更产生新版本；边界扩大自动冻结该区域，既有确认与核对结论全部作废
- **岗位名册 / 车辆设备**：人员（含岗位、班组、责任单位）与车辆设备（含活动门架）
- **门禁回执**：以回执号幂等录入，重复扫码不重复计数；名册在列但无任何回执的对象列为未决事项
- **班组确认**：班组负责人确认本组在某区域当前版本已撤离，绑定区域版本
- **倒计时里程碑**：封存后本体不可变，只能追加偏差说明
- **放行结论**：全部区域当前版本核对通过后由地面保障指挥发布；发布后出现冻结或核对变化时结论自动失效

### 冻结规则（任一未解除即禁止确认/核对/放行）

| 触发 | 说明 |
| --- | --- |
| `missing_receipt` | 名册对象无任何门禁回执 |
| `reentry` | 对象在班组确认/区域核对后重新进入危险区 |
| `boundary_expanded` | 区域边界扩大 |

冻结须由地面保障指挥排除原因后解除；原因未排除（如仍无回执）时冻结会再次出现。

### 角色与权限

| 角色 | 权限 |
| --- | --- |
| 班组负责人 `crew_lead` | 确认本班组状态、查看本组名册与区域状态 |
| 地面保障指挥 `ground_commander` | 核对区域、变更边界、解除冻结、发通知、封存里程碑、发布放行 |
| 发射指挥 `launch_commander` | 只能读取最终放行结论（`GET /releases*`） |
| 承包单位 `contractor` | 仅见本单位人员/车辆资料与通知，回执本单位通知 |
| 门禁系统 `gate_operator` | 录入门禁回执 |

### 指挥席看板

`GET /api/v1/dashboard` 与 `GET /api/v1/zones/:id/status` 提供：

- 各区域当前版本最后确认时间、确认明细
- 未撤离对象清单（人员/车辆、净在区数量、责任单位与班组）
- 未解除冻结及原因
- 依赖区域清场状态（按区域依赖给出未清场对象）
- 发往各责任单位的通知及回执时间

## 运行

```bash
go build -o evacsvc ./cmd/server
EVAC_DB=evac.db EVAC_ADDR=:8080 ./evacsvc
```

首次启动自动建库并注入演示数据（三个危险区、加注/消防/测量班组、跨午夜夜班 22:00–06:00、里程碑 M1–M3）。
演示账号：`gc-01`（地面保障指挥）、`lc-01`（发射指挥）、`lead-fuel`/`lead-fire`/`lead-measure`（班组长）、
`ctr-alpha`/`ctr-beta`（承包单位）、`gate-sys`（门禁系统）。请求经 `X-Actor-Id` 头标识身份。

## API 摘要

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/api/v1/gate-events` | 录入门禁回执（`receipt_no` 幂等，重复返回 200 + `duplicate`） |
| GET | `/api/v1/zones/:id/status` | 区域清场状态 |
| GET | `/api/v1/zones/:id/pending` | 未撤离对象及责任单位 |
| POST | `/api/v1/zones/:id/boundary` | 登记边界新版本（`expanded=true` 触发冻结） |
| POST | `/api/v1/zones/:id/crews/:crewId/confirm` | 班组确认（幂等） |
| POST | `/api/v1/zones/:id/verify` | 地面保障指挥核对区域 |
| POST | `/api/v1/zones/:id/notify` | 向责任单位发通知 |
| POST | `/api/v1/notifications/:id/ack` | 承包单位回执通知 |
| GET | `/api/v1/dashboard` | 指挥席看板 |
| GET | `/api/v1/freezes` / POST `/freezes/:id/resolve` | 冻结查询/解除 |
| GET | `/api/v1/personnel` `/vehicles` | 名册（按角色隔离） |
| POST | `/api/v1/releases` / GET `/releases` `/releases/latest` | 发布/读取放行结论 |
| POST | `/api/v1/milestones/:id/seal` `/milestones/:id/deviations` | 封存里程碑/追加偏差说明 |
| GET | `/api/v1/shifts/:id/receipts` | 班次窗口内回执（跨午夜正确归属） |

- `internal/core/scenario_test.go`

  - 里程碑：封存幂等，封存后只能追加偏差说明

## 设计要点

- **幂等**：门禁回执号唯一约束（重复扫码判重返回原记录）；班组确认以（区域，版本，班组）为主键；
  冻结以（区域，原因，对象）部分唯一索引去重；通知回执、里程碑封存均可安全重试。
- **事务与并发**：多步写入包裹在 SQLite 事务中；单连接 + busy_timeout 串行化写入，并发确认/扫码不产生重复记录。
- **版本化**：确认与核对绑定区域版本，边界变更后旧结论自然失效，杜绝"用旧确认放行走新边界"。
- **可恢复**：全部状态落库（WAL），缺回执冻结在状态计算时幂等同步，进程重启后未决清场事项不丢失。
